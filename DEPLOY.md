# Деплой на VPS

Бот состоит из двух частей с очень разными требованиями к серверу:

- **ядро** (Telegram, калькулятор, Google Sheets, ТТК, расчётка, идеи) — обычный
  Python-процесс, поедет куда угодно;
- **мониторинг конкурентов** — ходит по чужим сайтам, а они смотрят, с какого
  адреса и каким браузером к ним пришли. Здесь всё и упирается.

Поэтому порядок такой: сначала измерить, что пускает адрес будущего сервера,
и только потом решать архитектуру. Гадать бесполезно — блокировки зависят от IP
сильнее, чем от кода.

## Требования к серверу

| | Минимум | Комфортно | Почему |
|---|---|---|---|
| RAM | 2 ГБ | 4 ГБ | Chromium на пике ест около гигабайта; на 1 ГБ прогон уйдёт в OOM |
| Диск | 10 ГБ | 20 ГБ | профили браузера, сырые срезы, снимки таблицы, логи |
| ОС | Ubuntu 22.04+ | | под неё есть готовые пакеты Playwright |
| Локация | **Россия** | | с зарубежного адреса Лавка, ВкусВилл и Ozon упираются в гео-блок |

Отдельно про диск: каталоги `data/` (база конкурентов, профили браузера, сырые
срезы) и `backups/` (снимки листов Google Sheets перед каждой записью) **должны
переживать перезапуск и передеплой**. `backups/` — это защита данных шефа при
создании блюд, терять его нельзя.

Таймзона сервера значения не имеет: расписание задано с явным `Europe/Moscow`.

## Шаг 1. Установка

```bash
git clone <репозиторий> kitchen_bot && cd kitchen_bot
python3 -m venv .venv && source .venv/bin/activate
pip install -e .

# Браузер + СИСТЕМНЫЕ библиотеки. Без --with-deps на голом Linux не стартует
python -m playwright install --with-deps chromium
```

Секреты — как в README (шаги 2–4): `google_credentials.json` и `.env`.
Файлы с секретами на сервер класть отдельно, в git их нет.

## Шаг 2. Разведка — ДО того, как всё настраивать

```bash
python -m scripts.seed_competitors                      # завести список сайтов
python -m scripts.check_competitors --no-llm --brief    # кого пускает этот адрес
```

Вторая команда обойдёт всех конкурентов, ничего не запишет в базу и не потратит
денег на LLM. В конце напечатает таблицу вида:

```
ИТОГ (что пускает нас с этого адреса):
  OK   Додо Пицца (playwright)            7127 симв., цен 175
  НЕТ  Самокат (cdp)                      Chrome не запущен с отладочным портом
```

Признак успеха — не «ok», а **наличие цен**: страница-заглушка тоже бывает
длинной и осмысленной, но цен в ней нет.

Заодно проверить, что с этого адреса живут внешние сервисы:

```bash
python -m scripts.test_calc B119    # Google Sheets
python -m scripts.test_llm          # polza.ai (Ctrl+C для выхода)
```

## Шаг 3. Решение по результатам разведки

Что делать с сайтом, зависит от того, что показала таблица.

**Пустил (есть цены)** — ничего не делаем, метод в базе уже правильный.

**Не пустил, метод `playwright`** — сервер видят как датацентр. Варианты по
возрастанию сложности:

1. перевести сайт в `manual` — шеф сохраняет страницу и шлёт файлом боту.
   Работает всегда и везде, но это ручная рутина раз в пару недель;
2. попробовать `cdp` (ниже) — иногда помогает, потому что браузер запускается
   не Playwright'ом и без флагов автоматизации.

**Не пустил, метод `cdp` (Ozon, Самокат)** — им нужен запущенный Chrome:

```bash
python -m scripts.chrome_debug     # запускает Chrome с отладочным портом
```

На сервере без графической сессии скрипт сам добавит `--headless=new`. Дальше
два исхода:

- **сайт пустил** — повезло, дело было в флагах автоматизации, а не в куках.
  Ставим запуск Chrome в systemd рядом с ботом (юнит ниже);
- **показал капчу** — её некому пройти. Тогда либо Xvfb + VNC и разовый вход
  руками, либо `manual`. Для Самоката капча решаемая (повернуть картинку),
  и кука после этого живёт в профиле на диске.

⚠️ Не строй Xvfb+VNC заранее. Это отдельный сервис, который надо поддерживать,
а куки всё равно протухают. Ставь его, только если разведка показала, что без
него никак, и конкретный сайт того стоит.

## Шаг 4. systemd

Бот сам держит расписание внутри процесса (APScheduler), поэтому cron не нужен —
достаточно, чтобы процесс не падал.

```ini
# /etc/systemd/system/kitchen-bot.service
[Unit]
Description=Kitchen Bot
After=network-online.target

[Service]
Type=simple
User=kitchenbot
WorkingDirectory=/opt/kitchen_bot
ExecStart=/opt/kitchen_bot/.venv/bin/python -m src.bot.main
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now kitchen-bot
journalctl -u kitchen-bot -f
```

Если нужен постоянно запущенный Chrome для `cdp` — второй юнит с
`ExecStart=… -m scripts.chrome_debug`, `Restart=always` и тем же пользователем,
плюс `After=kitchen-bot.service` не нужен, порядок неважен.

Запускать **не от root**: Chrome под root требует `--no-sandbox`, а это лишнее
ослабление там, где мы открываем чужие страницы.

## Что проверить после запуска

```bash
python -m scripts.check_competitors --no-export   # полный прогон, ~20 мин на 8 сайтов
python -m pytest -q                               # 2 живых теста могут падать по таблице шефа
```

В Telegram: `/start`, `/refresh`, любой вопрос про UC, `/check_competitors`.

Первый еженедельный прогон стоит дождаться и посмотреть глазами: понедельник
03:30 МСК (конкуренты) и 04:00 (расчётка) — настраивается в `.env`.

## Известные грабли

**Chromium падает молча** — почти всегда мало памяти. `journalctl -k | grep -i
oom` покажет. Лечится увеличением RAM или swap.

**Прогон идёт 20+ минут** — так и задумано: между сайтами пауза 8–20 секунд,
это анти-бан. Проверка держит `asyncio.Lock`, второй запуск в это время получит
«проверка уже идёт».

**Sheets отвечает 403** — сервисный аккаунт не добавлен в таблицу (README, шаг 3).
На новом сервере ошибка та же, что и на старом, дело не в деплое.

**Всё было хорошо, потом сайт «сломался»** — прежде чем лезть в код, прогони
`--no-llm` и посмотри на текст. В 9 случаях из 10 это не парсер, а заглушка
антибота. Разбор таких историй — в CLAUDE.md, раздел про конкурентов.
